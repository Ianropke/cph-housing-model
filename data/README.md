# Point-in-time ML feature archive

`ml_feature_snapshots.jsonl` is generated by `scripts/daily_pipeline.py`.
Each row contains the eight live EWS inputs for one segment, the quarterly
price observation used for the later label, the pipeline timestamp, and the
source vintages used to construct each feature.

The archive is append-only and idempotent by `snapshot_id`. Daily snapshots
are not independent training observations: `scripts/train_ews_model.py`
selects the earliest recorded vintage per segment and observation quarter,
rejects snapshots retrieved after the forward-label horizon, and only then
creates the crash labels.

The model is not allowed to publish a probability until the archive contains
enough labelled history for walk-forward out-of-sample evaluation and at
least three independent crash episodes, with minimum labelled and OOS coverage
for each segment. Calibration folds are grouped by quarter so the three
segments from one observation period cannot be split across train and test.
Until then, the validation report is explicitly `INSUFFICIENT_HISTORY` and
production continues to publish `ml_crash_probability: null`.

The archive is not a historical backfill. Daily collection can only add the
currently published quarter. A historical backfill is allowed only when all
eight features can be reconstructed from authoritative, point-in-time sources.
In particular, current Boliga active-listing data has no historical series in
this repository, so that feature cannot be fabricated or silently proxied.
